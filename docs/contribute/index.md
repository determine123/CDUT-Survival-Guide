# 投稿与维护

欢迎不同专业、年级和去向，成功、失败与转向同样有价值。

## 网页投稿
1. 登录 GitHub，在个人 fork 编辑对应 Markdown 或新增文件。
2. 新增页面同时加入 mkdocs.yml 的 nav，文件名用小写英文短横线。
3. 创建 PR 到 main，说明来源、适用背景与改动。
4. 维护者检查事实、隐私、许可、链接和构建后决定合并。

无需安装工具即可编辑。不熟悉 Git 可在 issue 提交自己授权公开的文字，不上传证件和成绩单原件。

纠错注明页面、段落、时间和证据。保留不同背景，不发布可识别个人的未经核实指控。拒绝伪造案例、广告、代写代考与侵权转载。

投稿原创文字表示有权公开并按 CC BY 4.0 授权。第三方材料另行声明，维护者应保留原作者署名。

## 不安装工具，修改一段现有文字

1. 在手册页面点击编辑入口，或在仓库中找到对应的 `docs/` 下 Markdown 文件。确认文件与需要修改的页面一致。
2. 点击文件的编辑按钮。没有写权限时，按 GitHub 提示创建自己的 fork；把修改放在自己的分支，避免将无关改动混入投稿。
3. 修改后查看 Preview，检查标题、段落、链接和列表。写简短提交说明，例如“更正某通知的适用年级”，再提交改动。
4. 创建 PR 时核对 base repository 是本手册仓库、base branch 是 `main`，比较分支是自己刚修改的分支。查看 Files changed，确认只包含本次准备公开的内容。
5. 在 PR 中说明改了什么、适用背景、来源和授权；如果还没整理完，可以先使用草稿 PR。提交后等待检查和维护者反馈，在同一分支补充修改即可更新原 PR，不需要重新开多个相同 PR。

具体界面可参考 GitHub 官方的[网页编辑说明](https://docs.github.com/en/repositories/working-with-files/managing-files/editing-files)与[从 fork 创建 PR](https://docs.github.com/en/pull-requests/how-tos/create-pull-requests/creating-a-pull-request-from-a-fork)。网页预览不等于整个站点构建通过；自动检查或维护者还会核对导航和内部链接。

## 新文章与纠错分别准备什么

新文章先使用[投稿模板](templates.md)，在 `docs/` 的相应目录新增 Markdown 文件，并在 `mkdocs.yml` 的相关分类中加入标题与路径。不熟悉导航文件时，可先开草稿 PR 或 issue，请维护者帮助整理；正式收录前仍需补齐导航并通过检查。

纠错无需重写整章，说明页面、原句、希望修改的内容及依据即可。可按以下结构提交 issue：

```text
页面链接与段落：
当前文字的问题：
建议改成什么：
依据、发布日期与适用范围：
仍需核实的地方：
```

维护者可能追问年份、结果阶段或授权范围，这些用于确认能否收录。仅关闭 issue 不代表文字已发布，PR 被合并后也要等发布流程完成；需要查看最终结果时，核对线上对应页面。

GitHub 的 issue、PR、附件和提交历史通常公开可见。昵称署名不使提交账号匿名；公开前删除不愿披露的身份信息和第三方隐私。不上传证件、完整成绩单或未经授权的聊天截图。删除当前文字也不能保证历史和第三方副本消失。
