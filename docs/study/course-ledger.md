# 课程账本与学期计划模板

> 通用方法，整理于 2026-10-03；具体校内政策另行核查。

这是一份可以照着建立的私人记录，不是学校培养方案。请把本年级正式课程代码填进去。

## 每门课程记录
- 课程代码与名称、学分、类别、适用方案版本。
- 已修/计划修读、成绩、是否需要认定或补修。
- 先修要求、通常开课学期、实验和实践安排。
- 信息来源与确认日期，未确认的问题。

## 排学期的顺序
先放年度开课和毕业必需任务，再放其先修课程，随后处理补修，最后安排可调整选修。对每门课估计每周课内、作业、实验与通勤时间，用实际一周记录修正，不仅看学分。

## 一次模拟毕业审查
检查每类学分、必修课程、实践、毕业设计和学位条件。每项标成已完成、待完成、待认定或待确认；只有正式确认的部分才算完成。留出课程停开与补考的余量。

## 给老师的问题示例
“我是某年级从 A 专业转入 B 专业，已修课程代码 X。目标方案要求 Y，请问能否认定、需提交什么材料、何时办理？”这比只问“我能不能毕业”更容易得到具体答复。

本记录可能含成绩和学号，请保存在私人空间。公开投稿时只保留结构与已获许可的政策。

## 可以复制的单门课程记录

每门课程建立一条记录，课程名称用于阅读，课程代码和方案版本用于核对。下面的内容是待填写模板，不代表任何专业的实际要求。

```markdown
### [目标方案的课程代码] [课程名称]
- 适用方案：[入学年级、专业/方向、版本或文件日期]
- 目标要求：[课程类别、学分、必修/选修/实践属性]
- 当前状态：[未修 / 在修 / 已取得成绩 / 待认定 / 已获正式认定]
- 原专业对应课程：[代码、名称；没有则写无]
- 认定依据：[正式答复或文件位置；尚未确认则写待确认]
- 先修条件：[课程代码或其他条件；依据和确认日期]
- 开课安排：[已公布的学期；未公布则写待确认]
- 时间冲突：[与哪些课程、实验或实践冲突]
- 下一步：[向谁核对什么、自己安排的跟进日期]
```

已取得原专业成绩与已被目标专业认定是两个状态。等待认定的课程不要先计入“已完成”，也不要仅因名称相同就自行删除补修任务。同一门课能否用于不同类别，由适用方案和正式认定决定，不自行重复计算。

## 从毕业任务倒排到本学期

先确定期望完成的任务，再沿先修关系往前追溯，最后按时间从早到晚安排。比如抽象的“课程 A 是课程 B 的先修，课程 B 又是某实践的条件”，实际排课需要先完成 A，再完成 B，最后参加实践；字母仅为方法示例。

1. 写出最后一项必须完成的任务，以及它已确认的启动条件。
2. 对每个未满足条件继续追溯，直到找到本学期可以做的任务。
3. 给课程标出已公布的开课时间；不知道开课周期时先向学院核对，不将“往年春季开过”当作今年一定开。
4. 对时间冲突、名额限制、认定未完成等情况单列风险，核对是否存在获准替代方案。
5. 将考试、实践、毕设和申请手续都放进计划，保留无法如期完成时的调整路径。

倒排得到的日期是自己的规划，并不等于学校允许超修、跨年级选课或提前进入毕设。相关资格需要分别确认。

## 每学期结束的核对顺序

先核对成绩是否录入，再核对认定结果是否落实，最后按类别检查剩余要求。出现差异时保留课程代码、方案条款和系统状态，向负责该事项的老师询问。不要只截取系统总学分数字。

为每个未完成项保留“下一步”和“待确认事项”：是需要选课、补修、申请认定，还是仅等待成绩录入？改变其中一项后，重新检查依赖它的课程和毕业时间。
