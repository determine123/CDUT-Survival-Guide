# 人工智能学习：基础与可复现项目

> 整理：2026-10-03。通用建议、个人经历与政策分开阅读；当年官方文件优先。

以下是可调整的学习方法，不是成理某年级官方课程表。先与培养方案对照，保证必须课程完成。

数学从线性代数、微积分、概率统计和优化入手；编程掌握 Python、数据结构、调试、Git 和环境管理。每个主题完成可检查的练习，不只收藏教程。

先做一个小型监督学习项目：明确问题，划分训练、验证和测试数据，建立简单基线，记录指标与失败样例。保存数据来源、运行命令、随机种子与依赖版本。

随后探索视觉、语言模型、机器人或交叉方向。区分原作者方法、开源实现与自己的改动，没有复现结果时如实记录。调用模型不等于训练模型；应用项目也要验证质量、延迟与成本。

好的作品能让另一位同学运行，并知道你负责什么。项目深度往往来自解释与验证，不是工具名字的数量。

## 从一个可检查的问题开始

第一次项目可以只回答一个问题：给定合法可用的数据，能否完成一种明确预测，并解释在哪些样例上失败？先写输入、输出、评价方式和限制，再选择工具。不必同时加入界面、模型训练和部署；先确保主要实验能运行。

选数据时记录来源、使用许可和样本含义。公开数据也需要遵守其使用条件；来源不明或包含私人信息的数据不要直接发布。没有独立结果时，写明正在复现或学习，不提前声明优于原方法。

## 划分数据之后再学习预处理参数

训练、验证和测试各有用途。用于训练的变换参数应从训练数据获得，再应用到保留的数据；不能先用全部数据学习预处理，再切出测试集。反复根据测试结果挑选方案，会让测试结果失去独立检验的作用。

这些常见问题可参考 [scikit-learn 官方的预处理与数据泄漏说明](https://scikit-learn.org/stable/common_pitfalls.html)。同一个人、设备或原始样本产生的多条记录还需要结合任务检查关联性，不能仅因记录行不同就认定它们互相独立。

划分方式必须能解释真实使用场景。处理带有时间顺序的数据时，先问预测时能够知道哪些信息；不要使用未来才出现的信息作为当时可用输入。

## 先记录基线，再改变一个假设

基线是便于理解和比较的起点，可以很简单。先保存同一评价口径下的结果，再写下这次改动希望解决的问题。比较时说明哪些条件保持一致、哪些发生变化，避免把换数据或换评价方法造成的差异算作模型改进。

除汇总指标外，查看具体失败样例，说明是否集中在某类输入。一次结果不能证明稳定提升；随机性、样本规模和任务差异都应在报告中交代。没有可靠记录时，报告实际观察和限制即可。

## 一个最小实验记录

```markdown
### [实验名称与日期]
- 问题与假设：[本次要确认什么]
- 数据：[来源、版本、使用条件与划分方式]
- 基线：[方案、运行配置及记录位置]
- 本次改变：[具体改动，其他变化也如实注明]
- 运行：[环境、命令、参数、随机性设置]
- 观察：[结果及代表失败样例]
- 结论：[支持或不支持假设；尚未确认的部分]
- 下一步：[一项需要继续检查的事]
```

使用模型 API 的项目也可以按这个结构验证：准备获准使用的样例，记录请求设置和回答检查方法，并在项目中说明外部服务的依赖。调用服务、调整提示和训练模型分别表述，不混成同一项能力。
